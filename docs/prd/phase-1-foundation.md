# PRD — Phase 1: Foundation & Infrastructure

## Overview
Stand up the full monorepo skeleton with a working Next.js frontend, FastAPI backend, PostgreSQL database, and Docker Compose local dev environment. No business logic — only the scaffolding that every subsequent phase builds on.

## Goals
- Developers can clone the repo and run `docker compose up` to get a fully working local stack.
- The frontend, backend, and database can communicate with each other.
- OpenAPI spec is auto-generated from the FastAPI routes and viewable via Swagger UI.
- A CI pipeline runs lint and type checks on every push.

## Out of Scope
- Any trip planning logic.
- Authentication / user accounts (Phase 2).
- Any mapping or routing integration.

---

## Tech Stack
| Layer | Technology |
|---|---|
| Frontend | Next.js 15 (App Router), TypeScript, Tailwind CSS |
| Backend | FastAPI, Python 3.12, Pydantic v2 |

| API Spec | OpenAPI 3.1 (auto-generated by FastAPI) |

### docker-compose.yml Services
- `frontend` — Next.js dev server, port 3000, hot reload via volume mount
- `backend` — FastAPI with uvicorn, port 8000, hot reload via volume mount
- `db` — PostgreSQL 16, port 5432, named volume for persistence
- `adminer` — lightweight DB GUI, port 8080 (dev only)

### Backend Requirements
- `GET /health` — returns `{"status": "ok", "db": "connected"}` (checks DB connectivity)
- `GET /docs` — Swagger UI (FastAPI default)
- `GET /openapi.json` — raw OpenAPI spec
- Environment config via `.env` file loaded through `pydantic-settings`
- Async SQLAlchemy session factory wired into FastAPI dependency injection
- Alembic configured; initial migration creates an empty baseline

### Frontend Requirements
- Home page (`/`) renders a placeholder "Road Trip Planner" heading
- An API client utility (`src/lib/api.ts`) that reads `NEXT_PUBLIC_API_URL` from env and exports a typed fetch wrapper
- `next.config.ts` rewrites `/api/*` → backend in local dev so CORS is not needed in dev

### Environment Variables
**Backend `.env`**
```
DATABASE_URL=postgresql+asyncpg://postgres:postgres@db:5432/travel_planner
SECRET_KEY=changeme
ENVIRONMENT=development
```

**Frontend `.env.local`**
```
NEXT_PUBLIC_API_URL=http://localhost:8000
```

### CI (GitHub Actions)
- Trigger: push to any branch, PR to `main`
- Jobs (run in parallel):
  - `frontend-ci`: `pnpm install`, `pnpm typecheck`, `pnpm lint`
  - `backend-ci`: `uv sync`, `ruff check`, `mypy app/`

## Acceptance Criteria
- [ ] `docker compose up` starts all services with no manual steps beyond copying `.env.example`.
- [ ] `GET http://localhost:8000/health` returns 200 with DB connected status.
- [ ] `GET http://localhost:8000/docs` loads Swagger UI with no errors.
- [ ] `GET http://localhost:3000` renders the placeholder home page.
- [ ] `pnpm typecheck` and `pnpm lint` pass with zero errors.
- [ ] `mypy app/` and `ruff check` pass with zero errors.
- [ ] `alembic upgrade head` runs without error against the local DB.
- [ ] CI pipeline passes on a fresh branch with no local changes.

## Notes for the Implementing Agent
- Use `asyncpg` as the PostgreSQL driver (not psycopg2) to support async SQLAlchemy.
- Pin all Python dependencies in `pyproject.toml` under `[project.dependencies]` with minimum versions.
- The `docker-compose.override.yml` pattern keeps prod-unsafe settings (Adminer, volume mounts) out of the base file.
- Do not add any business-logic routes in this phase — keep `main.py` minimal.
- Tailwind should be initialized via the official Next.js + Tailwind setup; no custom design system in this phase.
